# Phase 5C.2 — Future evaluation protocol draft

Artifact status: **DRAFT FOR EXTERNAL REVIEW**. No production, evaluator, retrieval, reranking, benchmark, semantic judge, bootstrap or API/network execution occurs in this phase. This protocol is not frozen or executable authorization. Every numerical design threshold below is a proposed prospective choice for external review, not tuned on the frozen 31 queries or observed challenge outcomes.

## 1. Estimands and comparison arms

**31-query / 102-point benchmark remains the primary HISTORICAL COMPARABILITY BENCHMARK.** Since it informed the requirements, **the 31-query benchmark is no longer an untouched confirmatory holdout** for v2. Retain its exact scoring/labels and report future historical compatibility separately; do not pool its points with challenge points or use it alone to claim generalization. Frozen Answer Revision = **Insufficient evidence** and Evidence Expansion = **Insufficient evidence**.

The primary future estimand is mean paired v2−v1 change in query-level Answer Completeness on independently constructed HOLDOUT TEST items that have corpus-answerable substantive gold aspects, averaged across all preregistered production repetitions. Report the target construction distribution and effective independent cluster count. This does not estimate all legal-domain generalization. Report separate answerability, safety and calibrated-disclosure outcomes on every TEST item, including zero-answerable-point items.

| Arm | Purpose | Frozen/common components and permitted differences |
| --- | --- | --- |
| S: Standard RAG frozen architecture | S vs V1 asks whether v1 agentic behavior helps this challenge distribution | Initial retrieval, final Top-5, generation model, corpus and evaluation method common; Standard retains its frozen single-pass architecture |
| V1: Agentic v1 frozen architecture | Fresh challenge baseline | Frozen reference controller/prompt/budgets; no use of old R1 answers because no historical challenge answers exist |
| C: Candidate completeness/goal bundle | V1 vs C investigates checker/revision/goal-tracking package if independently authorized | Only predeclared completeness behavior changes; v1 expansion policy remains fixed. If R3 confirmation fails, omit R3 and name C accurately |

S, V1 and final v2 are the minimum system comparison. Preferred minimal attribution plan has four arms S/V1/C/E, avoiding a full factorial. The names describe candidate contrasts, not a mandatory implementation order. If expansion is not authorized, C is final v2 and expansion contribution remains untested. If C includes several mechanisms, V1→C supports only a bundle-level claim; draft/final localization is not proof of isolated R1/R2/R3 causality. An additional C-without-R3 arm is an **UNTESTED DESIGN OPTION** only if a separate goal-persistence effect is needed, with independent authorization and cost review. No A3/A4 runs are proposed for this phase.

All arms receive identical query bytes, corpus hash, initial retrieval base/index/reranker, generation-model resolved version/config, evaluator version and annotation protocol, except predeclared architectural prompt/policy differences. Do not modernize S/V1 prompts while calling them frozen. Capture model/backend revision or unavailable provenance; if exact historical provider identity cannot be pinned, describe these as prospective architecture comparisons under the same contemporary model, not exact historical run reproductions. No provider verification/network occurs now.

Use common offline-verified environment/config hashes and the frozen-reference Top-5, BM25@20∪Dense@20 base, one expansion episode, three subqueries, one answer revision, one citation revision and six logical agentic LLM calls. A richer checker cannot silently gain more calls/context. CPU retrieval/reranking must be planned and measured separately. Any additional budgets are **UNTESTED DESIGN OPTION** and require separate DEV validation and declared contrasts before TEST.

## 2. Production–evaluator isolation and sealing

Carry forward [Phase 5A §5 isolation design](../phase5a_ablation_spec_v0.md): a trusted custodian creates a strict query-only projection with opaque ID and exact query string. Production process and wrapper receive only this projection plus minimal resolved runtime configuration. Full design/gold/evaluation manifests remain in trusted orchestration, not production.

Production filesystem allowlist: reviewed runtime sources/dependencies/model caches, locked corpus/index, query-only input and per-run output namespace. Deny gold, required points, gold evidence labels, reference answers, difficulty/dimension/answerability labels, TEST quality outputs, prior benchmark analyses and historical answer traces. Deny access through resolved symlinks, imports, inherited handles/memory/environment, stdin and logs. No evaluator imports in the production dependency closure. Opaque IDs may not encode family, difficulty or expected behavior. Construction/annotation and implementation use separated human/agent contexts; an implementation agent already shown TEST gold cannot be made blind by deleting a local file.

Before future live execution, require separately implemented offline synthetic isolation checks: import/source boundary; exact projection extra/nested-field rejection; denied reads through aliases; synthetic sentinel cannot enter prompts/state/traces; production can finish with gold absent; evaluator joins only sealed output hashes. These are requirements to validate later, not tests executed or security guarantees established in 5C.2. Runtime access to gold remains FORBIDDEN even for DEV; implementers may use DEV gold offline to diagnose behavior.

Before TEST: seal dataset/split, source/config/prompts, all arms, production order, repeat count, evaluator/rubric, primary contrast, margins, subgroup definition, uncertainty method, budget and retry policy. Execute all systems and all repeats without viewing quality. Retain immutable per-attempt output/error envelopes and call ledgers. At the end, seal every scheduled slot, raw production traces and hashes before the evaluator can join gold. Evaluator may join gold only after all planned production outputs across systems and repetitions are sealed. Quality-triggered reruns, best-of-N selection, architecture edits between repeats and dropping failed queries are prohibited.

If quota fails, pause on resource grounds, record started/failed/ambiguous slots and resume only under the preregistered recovery policy with identical config; never choose retries based on quality. Preferred policy: no retry of an accepted production answer; at most one transport retry only after definitively failed/no-output attempt, all attempts logged, ambiguous timeout retained for adjudication of execution status rather than duplicate guessing. Judge parse/transport recovery likewise preserves attempts and the first valid response under the fixed policy, not the most favorable judgment. More transport attempts require an explicit protocol amendment before outcomes are examined. Successful subset reporting is secondary only; incomplete planned slots prevent a full confirmatory PASS.

## 3. Repeated-run and uncertainty strategy

Preferred: **three independent production runs per query per arm**, scheduled in balanced/interleaved system blocks with a fixed published scheduling seed chosen before TEST. A seed for order is not a promise of deterministic generation or common random numbers across APIs. Hold model settings and prompts constant; save request parameters and backend provenance. Budget and execute all runs before quality feedback. Minimum acceptable: **two total production runs**, declared before TEST if resources cannot support three; report a replicated comparison and observed run sensitivity with weak stochastic characterization, not a reliable variance estimate. Stronger optional: **five production runs**, also predeclared, for more useful run sensitivity. A single R1→R2 replication is never called a variance estimate or used as a correction subtracted from new effects.

Keep three uncertainty sources separate:

| Source | Proposed analysis | Limits |
| --- | --- | --- |
| Query sampling | Paired resampling of independent scenario clusters within predeclared primary-family strata; retain all systems, points and production repetitions for each sampled cluster, then average repeats | Proposed 10,000 resamples and 95% percentile interval, seed 20260910; no bootstrap run now. This conditions on observed generation/judging and is not their uncertainty. Purposive challenge sampling limits population interpretation |
| Production stochasticity | Per-query and aggregate metrics for every repeat, all paired block deltas, same-config churn and descriptive run dispersion; balanced order reduces temporal confounding | Three repeats give a fragile dispersion estimate; two give only minimal observed sensitivity. Query points and runs are not independent extra queries. Backend drift is a separate confound |
| Semantic judge stochasticity | Main blinded judgment of every sealed answer; predetermined eight TEST-query subset receives three independent judge passes on each identical final output across all arms/runs | Choose subset by hash/stratified custodian selection before outputs; no selection of disagreements or favorable examples. Judge repeats keep answer/evidence bytes fixed and are distinct from production repeats |

For the judge audit, use two additional passes beyond the main first pass; first valid main judgment remains the primary metric record. Report label agreement/disagreement and metric ranges across passes. Blinded legal review resolves meaning/rubric issues and flags unstable cases; any adjudicated sensitivity set is applied symmetrically to all arms. Do not let majority voting chosen after seeing differences determine the headline. Eight queries is a resource-limited variability audit, not a global judge-variance guarantee. Broader triple judging is a stronger optional protocol to predeclare if feasible.

Preferred primary CI is a query/cluster-sampling interval conditional on observed runs. Publish production and judge sensitivity alongside it, and do not label that interval a joint uncertainty CI. A future hierarchical joint analysis requires review and adequate independent run/cluster counts before TEST; it must not treat 32×3 trajectories as 96 independent legal tasks. If directions depend on a repeat, the CI touches zero, cluster support is too sparse or judge re-scoring reverses the effect, retain an inconclusive interpretation.

## 4. Metric definitions and denominator rules

All semantic metrics below are computed **evaluator-side after sealing**, using independent gold plus retained outputs and stage evidence. Runtime may estimate similarly named concepts using its own ledger, but those estimates are tagged `runtime_estimate` and cannot read or stand in for gold.

For query q, let P+(q) be its adjudicated required substantive aspects with sufficient applicable corpus support. Let U(q) be scoped material asks/portions requiring unresolved/partial-support disclosure. Let Q(q) be gold obligations to state the supported, qualified portion of a partial-support aspect; these remain distinct from full P+ aspect credit. Let A(q,r,s) be final answer claims, with an atomic claim segmentation rule frozen before TEST. P+, Q and U can refer to distinct portions of one broad ask; their scoring obligations must be disjoint and set before system outputs. A Q obligation cannot be satisfied only by disclosing U, and a narrower Q statement does not earn full credit for its partially supported parent aspect. Do not create these aspects now. Correct conditional propositions count only if their conditions are preserved. Context-only or not_applicable evidence cannot justify a substantive claim.

Report raw numerator/denominator, per-query macro means and pooled ratios separately. Primary AC averages per-query ratios over P+ nonempty queries and then across all production repeats; micro pools substantive points. Dimension summaries are overlapping descriptive strata, not additive populations. Zero denominator = null/not_applicable, never 1 or 0 by convenience; report eligible counts. Empty/error outputs receive AC=0 for P+ nonempty items and fail response adequacy; claim safety ratios are undefined for no claims, accompanied by error/abstention rates so silence cannot look perfectly safe. Failed/unreached mechanism stages are reported separately and never counted as successful zero-cost interventions.

### Answer-level metrics

| Metric | Numerator | Denominator / qualification |
| --- | --- | --- |
| Answer Completeness (primary) | P+ aspects correctly and substantively covered with appropriate scope/conditions | All P+ aspects for that query; disclosure alone gives no credit. Macro over P+ nonempty queries; zero-P+ items excluded from AC but included in adequacy/abstention |
| Citation Completeness | Covered P+ aspects whose attached citations collectively support the aspect with valid applicability | All P+ aspects; answer omission or absent support-linked citation yields no credit |
| Citation Correctness | Cited atomic legal claims whose attached cited evidence collectively entails the claim under its qualifications | All atomic legal claims with citations; separately report invalid/unknown citations and claim–citation-link precision so irrelevant extra citations are visible |
| Groundedness | Atomic legal claims fully supported by the exact evidence available to that answer stage with valid applicability | All asserted atomic legal claims; a legally plausible claim from outside available evidence is not grounded |
| Unsupported Claim Rate | Atomic legal claims not fully supported by that stage's available applicable evidence | All asserted atomic legal claims; partial/contradicted/unverifiable support counts unsupported under binary rubric, with separate reasons |
| Unresolved disclosure coverage | U obligations with specific, accurate limitation disclosure without an invented legal answer | All U obligations; do not credit generic blanket uncertainty that conceals known supported content |
| Qualified-partial coverage | Q obligations correctly stated within their supported scope and with appropriate qualifications | All Q obligations; separate from full substantive AC credit |
| Bounded response adequacy | Items with all P+ covered, all Q qualified portions stated, all U correctly disclosed, preserved conditions, no unsupported legal claims and valid required citations | All scheduled query-run outputs, including fully/partially/insufficient answerability and failures; fully adequate partial response is not full legal answerability |

Answerability-aware AC intentionally excludes unsupported-in-corpus substantive asks rather than awarding hallucinations or forcing an unattainable score. Always report Q/qualified-partial coverage, U/disclosure, answerability-stratified adequacy and exclusion counts beside AC. This is a new challenge definition; historical metrics remain unchanged and are not numerically pooled with it. Unsupported Claim Rate and Groundedness are complements under this binary rubric; they are not independent evidence of safety. Empty/abstaining answers cannot win by shrinking claim counts: show totals, macro/micro, coverage and adequacy together.

### Controller calibration

| Metric | Numerator | Denominator / notes |
| --- | --- | --- |
| Internal complete vs evaluator complete | Full 2×2 counts of internal full-complete true/false against evaluator full scoped completeness; plus separate unknown/unreached row | All outputs; evaluator full scoped completeness requires all material requests substantively answerable/answered with conditions and no unresolved material asks, while evaluator adequacy permits disclosed partial answers |
| Status calibration | Confusion matrix runtime status vs independently derived full/partial-adequate/insufficient-adequate/incomplete/citation/error outcome | All scheduled outputs; legacy V1 success remains original status and is mapped for analysis only, not rewritten in traces |
| False-success rate (full) | success_complete predictions that are not evaluator full-complete; V1 legacy success analyzed as its own full-success claim | Outputs predicting that full-success status; also report false-success count / all outputs |
| False-success rate (partial) | success_partial_with_disclosure predictions failing evaluator bounded response adequacy | Outputs with that partial-success status; never count a well-disclosed partial answer as full complete |
| False-insufficient rate | Runtime insufficient_evidence outputs on items with at least one material substantively corpus-answerable portion | Outputs predicting insufficient_evidence; break down fully vs partially answerable gold and whether available final evidence also supported an answer |

A false-insufficient case may be a retrieval failure rather than a checker failure; cross-tab corpus support vs available evidence before attributing cause. `verification_incomplete` is not a false complete. Lack of a legacy status field is not a negative prediction. Quote denominators when comparing status taxonomies with different prediction frequencies.

### Expansion metrics

| Metric | Numerator | Denominator / pairing |
| --- | --- | --- |
| Expansion trigger rate | Decisions authorizing expansion | Runs reaching the expansion decision; also report actual attempted / all scheduled runs and unreached counts |
| Evidence gain | Evaluator P+ aspects newly sufficiently supported after expansion relative to initial evidence; subtract and report support losses separately | All P+ for a normalized coverage delta; also report mean counts per attempted expansion. Candidate pool and retained final Top-5 are separate scopes |
| Newly resolved aspects | Previously partial/unsupported scoped aspects now fully supported by applicable evidence | Previously unresolved evaluator-mapped aspects at expansion entry; all-attempt mean counts additionally reported |
| Retrieval overhead | Retrieval calls with expansion minus one initial baseline; merge-rerank operations reported separately | Per scheduled trajectory and per attempted expansion; failures and transport retries remain in ledgers |
| No-value expansion rate | Completed expansions with no new applicable final support and no verified useful condition clarification | Completed expansion attempts; report failed attempts separately and attempted-but-no-demonstrated-value / all attempts |
| Expansion attributable answer benefit | Paired C→E AC/adequacy changes with evidence gain/loss paths retained | All predeclared TEST items and independently defined D6/D4/D5 strata, across repeats; triggered-only summaries are descriptive post-treatment subsets |

A novel chunk/article/document is not automatically useful. Final Top-5 changes without support gains can be no-value. Report evicted evidence, irrelevant additions, applicability failures and uncertainty. Runtime-identified new aspects are not substitute evaluator denominators. Legal support gain without final answer recovery is an intermediate outcome, not final benefit.

### Revision metrics

| Metric | Numerator | Denominator / pairing |
| --- | --- | --- |
| Draft→final point recovery | P+ aspects absent in draft and correctly present in final answer with applicable support | Draft-missing P+ with sufficient support in the revision-input evidence; report gains/losses/net over all P+ too |
| Supported-claim change | Number of fully grounded final claims minus fully grounded draft claims | Mean per completed revision pair; separate added/removed claim mappings, not a fictitious fixed paired-claim universe |
| Unsupported claims introduced | New or materially changed final claims unsupported by revision-input evidence | All new/materially changed legal claims from revision; additionally count per completed revision and report zero-new-claim pairs as N/A |
| Revision cost | Revision plus dependent recheck logical calls/tokens/time and HTTP attempts | Per attempted revision and per scheduled query, including failed attempts; citation repair separated |
| Mechanism-localized recovery | Recovered P+ whose supporting evidence was already in the revision-input snapshot and whose semantics first appear in revised answer | All recovered P+ in preserved draft/revised pairs; later citation-only edits are not semantic recovery |

Score draft, revised and final outputs against their own evidence/answer hashes, not final evidence retroactively. If citation editing alters semantics, show draft→revised and revised→final separately. Draft-final gains alone do not establish the causal effect of the new revision policy; pair with controlled arm contrasts and repeated runs. Missing intermediate artifacts mean unmeasurable, never zero effect.

### Goal persistence metrics

| Metric | Numerator | Denominator / audit unit |
| --- | --- | --- |
| Supported applicable aspects identified | Distinct P+ aspects independently mapped to an admitted runtime aspect | All P+ sufficiently supported by some controller-visible evidence stage; also report / all P+ to reveal retrieval limits |
| Supported applicable aspects answered | Identified answer-worthy aspects with applicable support at generation/revision input that appear correctly in final answer | All such independently validated identified aspects; deduplicate merged IDs and separate support lost through context eviction |
| Unresolved aspects correctly disclosed | Identified explicit/admitted asks independently unresolved at final evidence stage with accurate final disclosure | All identified explicit/admitted asks independently unresolved at that stage; corpus-known answerability cross-tab distinguishes retrieval failure |
| Aspect disappearance rate | Previously identified aspect IDs absent from a later expected ledger snapshot without merge/exclusion/terminal event | All unique (aspect ID, expected subsequent snapshot) opportunities; also report affected unique IDs / identified IDs and affected queries / observable queries |

Any identified candidate must remain traceable, but excluded unsupported inferred candidates are not required answer content. False promotions/overgeneration are audited as unsupported or irrelevant admitted aspects / all admitted inferred aspects. A valid exclusion with a reason is not disappearance. Legacy unretained state is `unobservable`, not proof of disappearance and not a zero failure. R3 confirmation requires observable independent cases before intervention.

## 5. Prospective evidence and acceptance gates

Separate **problem confirmation/implementation gate** from **intervention adoption gate**. Before implementation, require reviewed requirements, corpus-first frozen splits, DEV-only evidence of the target failure/opportunity, legal annotation agreement, budget/isolation feasibility and explicit later authorization. R3 additionally needs at least three independent DEV cases across at least two task families/scenario clusters with stage evidence and competing explanations reviewed; the medical diagnostic does not count. This minimum is a proposed replication floor, not confirmed prevalence. If observability is insufficient, R3 remains deferred.

For future adoption, proposed reviewable margins are: minimum practically meaningful primary macro AC gain **0.05 absolute**, maximum allowed deterioration in macro and pooled Groundedness/Citation Correctness **0.02 absolute**, and maximum increase in macro and pooled UCR **0.02 absolute**. These are normative draft tolerances, not calibrated from 31-query outcomes; legal reviewers must accept or amend them before TEST. Proposed budget gate retains frozen-reference call ceilings and reports cost per additional correctly covered substantive aspect; no token-price claim without actual ledgers. Any newly introduced high-severity unsupported legal duty/application identified by blinded legal review blocks adoption even if aggregate margins pass. Severity rubric must be approved before TEST.

Proposed evidence rule for the primary E−V1 claim: mean gain at least the reviewed practical margin; paired cluster query-sampling interval lower endpoint above zero; positive aggregate direction in each of the preferred three predeclared production blocks; no reversed overall conclusion on fixed-output judge sensitivity; safety noninferiority bounds within the reviewed margins for both macro and pooled summaries (lower bound of benefit-oriented Groundedness/Citation Correctness delta at least −0.02, upper bound of UCR delta at most +0.02 under the proposed margins); completed trace/isolation/cost records and all scheduled outputs accounted for. Three same-direction repeats alone are not a significance test. A small TEST may not resolve the intervals: the proper outcome is inconclusive, not relaxed thresholds or selective extra runs. Under the minimum two-run protocol, report replicated evidence with limited stochastic characterization; strong mechanism attribution remains provisional pending the stronger protocol.

| Candidate | Additional adoption evidence required | If absent |
| --- | --- | --- |
| R1 Answer Revision | Repeatable draft→revised supported-point recovery localized to supplied applicable evidence across independent queries; checker/repair errors and draft losses reported; bundle/optional isolated contrast consistent with gain; no unacceptable grounding/citation deterioration; revision/recheck cost reported | Keep research candidate or refine; do not relabel historical Answer Revision |
| R2 Checker | Lower false full-success and improved status calibration, without simply predicting insufficient on answerable items; evidence/answer/scoped-query distinction demonstrable and false-insufficient/cost reported | Refine spec or defer; no software-bug claim from mismatch alone |
| R3 Goal persistence | First establish multi-case problem on DEV; then fewer independently verified disappearances/undisclosed unresolved asks and better answered coverage without promoting unsupported inferred content | Remain hypothesis/defer; bundle gains do not isolate R3 causality |
| R4 Expansion | C→E evidence gains linked to answer/adequacy gains, in aggregate or predeclared independently labeled D6/D4/D5 target stratum; benefit stable across repetitions beyond observed run sensitivity, safety acceptable, costs justified | No claim that expansion is useless or proven beneficial; investigate selectivity and exposure limits |
| R5 Challenge evaluation | Independent construction, legally reviewed schema, dimension/cluster audit, DEV/TEST access separation and sufficient observed eligible cases | Revise design before future execution; no claim that current benchmark is easy or replaced |
| R6 Attribution safeguards | Full provenance, all-run/no-selection audit, separate uncertainty sources, consistent macro/micro safety and paired point transitions | Attribution invalid or inconclusive regardless of headline gain |

Triggered-case recovery/value must be reported, but triggered strata depend on each system's decisions and cannot establish randomized subgroup causality. Use predeclared corpus/D6 strata for targeted comparisons, show all eligible denominators and expose trigger disagreements. If D6 exposure is below its target, targeted expansion confirmation is not supported; full-set comparisons still report what was observed. No causal claim from one query.

Only E−V1 AC is the primary confirmatory contrast. S−V1 (reported in the direction V1−S), C−V1 and E−C are secondary planned contrasts. Avoid multiple unadjusted definitive mechanism claims: for formal secondary mechanism claims, predeclare simultaneous intervals using Bonferroni confidence level 1−0.05/m for the m registered secondary contrasts; otherwise label them descriptive. Dimension and mechanism metrics are diagnostic with exact denominators, not a large significance fishing exercise. If full v2 is C instead of E, rewrite/seal contrast list before TEST, never after outcomes.

## 6. Resource ledger and execution completeness

Preferred 32 TEST × 3 repeats × 3 main systems = 288 trajectories; four-arm attribution = 384. Main/four-arm logical production LLM ceilings = 1,248/1,824, retrieval-call ceilings = 864/1,248, plus merge-reranking CPU. These are conditional reference budgets, not quota promises. See [sampling rationale](phase5c2_challenge_set_design_v0.md). Every stage logs logical call, physical attempt, success/failure, known token usage, latency and unknown/missing usage separately. Judge attempts are never included in production LLM counts.

If every retained agentic draft receives one semantic judgment, three-arm draft objects = 192; four-arm = 288. Final judgment objects = 288/384. Fixed eight-query judge-audit subset adds two passes × eight × three repeats × three/four systems = 144/192 additional judgment objects. Thus planned base judgment objects including drafts and repeated final auditing = **624/864**, before any third answer version, adjudication or recovery. A judgment object may require multiple evaluator API calls under the later chosen evaluator; these numbers are not API-call totals. No evaluator is invoked now.

Predeclare DEV budget independently; DEV-only diagnosis does not justify uncontrolled future cost or TEST access. Quota-constrained minimum two-run or smaller cohort decisions must be made before TEST outcomes. Model/backend changes mid-run require a logged protocol decision and potentially a new compatible cohort; do not pool incompatible versions silently. Missing slots produce execution-incomplete reporting; retain all intended denominators, provide conservative error treatment and secondary available-case analyses distinctly.
